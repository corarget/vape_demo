# RUNBOOK — сборка, релиз, резервное копирование и диагностика

## Перед релизом

1. Убедиться, что выбран нужный Worker и D1 в `wrangler.jsonc`.
2. Выполнить `npm ci` и `npm run release:check`.
3. Не публиковать при ошибке тестов, миграций или dry-run.
4. Создать резервную копию: `npm run backup:d1`. Сохранить SQL и JSON-манифест вне репозитория.
5. Публикация выполняется Workers Builds из `main`; после неё проверить build outcome, version и deployment 100%.
6. Выполнить `SMOKE_BASE_URL=https://... npm run smoke`.

## D1: резервное копирование и восстановление

Cloudflare D1 автоматически поддерживает Time Travel. Перед изменением данных зафиксировать bookmark командой Wrangler/Dashboard и целевой database_id. SQL-export создаётся `npm run backup:d1`; рядом записывается SHA-256 и размер.

Восстановление считается разрушительной операцией и не автоматизировано. Порядок:

1. Остановить запись или объявить окно обслуживания.
2. Ещё раз проверить account, Worker, имя и database_id.
3. Предпочесть Time Travel restore на нужный bookmark.
4. Для SQL использовать только проверенный export с совпадающим SHA-256 и команду `wrangler d1 execute DB --remote --file=<backup.sql>` после отдельного подтверждения.
5. Повторить smoke-test и проверку целостности; задокументировать время и исполнителя.

## Rollback кода

Rollback версии Worker не откатывает D1 и внешние данные. В Cloudflare выбрать предыдущую проверенную версию и создать deployment на 100%, затем выполнить smoke-test. Если релиз включал миграцию, сначала оценить совместимость старого кода с новой схемой; автоматический downgrade схемы запрещён.

## Диагностика

- Проверить Workers Build, активную версию и процент трафика.
- Проверить `/api/health`, главную страницу, админку и статические assets.
- Смотреть Workers Logs по событию и времени. Логи не должны содержать cookie, токены, телефоны, Telegram payload, адреса или тела заказов.
- Проверить ошибки D1, последние миграции и доступность Google Sheets без вывода секретов.
- При инциденте сохранить request time, route, status, build/version/deployment; не копировать персональные данные.

## Критические ограничения

Техническая приёмка не означает юридическую или коммерческую готовность. До запуска остаются решения о юрисдикции, операторе данных, сроках хранения, удалении данных и обработке запросов субъектов.
