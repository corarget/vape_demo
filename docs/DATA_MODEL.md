# Этап 2 — контракт данных (версия 2)

## Источники и границы ответственности

| Данные | Канонический источник | Производные / копии |
| --- | --- | --- |
| Записи и категории | Google Sheets, ровно два листа | CSV-представление и временный cache |
| Изображения | HTTPS URL в исходной строке | Медиа-сервис хранит байты, не метаданные |
| Операционные записи | D1 конкретного окружения | Исторические снимки и журнал |
| Сотрудники, роли, сессии | D1 | Никакой записи в Sheets |
| Конфигурация | D1 settings; env как начальное значение | Публичное подмножество |
| Секреты | Cloudflare secrets | Не хранить в таблице или Git |

У каждой сущности один владелец. D1 не создаёт постоянные альтернативные копии записей Sheets. Кэш не является источником истины. Исторический снимок в order_items не является дубликатом каталога: он фиксирует состояние на момент записи.

## Схема Sheets

Товары: product_key, sku, category, name, option_label, price_byn, image_url, available, active, brand, strength_mg, variant_image_url.

Категории: id, name, image_url, active, sort_order.

- Одна строка соответствует одной записи-варианту; sku — стабильный уникальный идентификатор во всём листе (без учёта регистра и пробелов).
- product_key — стабильный идентификатор группы; повторения внутри одной группы допустимы. Один ключ не должен принадлежать нескольким группам, одна группа не должна иметь несколько ключей.
- category ссылается на точное значение categories.name. id — отдельный уникальный slug. Удалённый product_category во всех девяти строках совпадал с name. Не переименовывать категорию без согласованного изменения ссылок. brand заменяет прежний заголовок manufacturer; импорт поддерживает этот алиас.
- active и available — отдельные нативные boolean-ячейки с чекбоксами; цена неотрицательная, с точностью до двух знаков, D1 хранит денежные суммы в целых минимальных единицах.
- URL изображений — HTTPS либо пустая строка. URL не гарантирует доступность самого ресурса.
- Не менять существующие идентификаторы произвольно; не использовать номер строки как идентификатор.

## Совместимость текущего runtime

Существующий catalog.mjs группирует по нормализованным текстовым полям и строит family:… ID. Это вычисляемое представление, а не постоянный ключ. Его смена требует миграции ссылок и регрессионных тестов; на этапе 2 его не меняем. В существующих данных product_key согласован с группировкой. SKU остаётся каноническим идентификатором записи в контракте, но старые runtime IDs сохраняются для совместимости. Не смешивать product_key и sku.

## Схема D1

| Сущности | Таблицы |
| --- | --- |
| Операционные записи и их история | orders, order_items, order_events, order_numbers, order_recovery_sessions |
| Пользователи и доступ | staff, staff_invites, sessions, demo_login_attempts |
| Настройки, временные ограничения | settings, slot_blocks |
| Диагностика | analytics_events, sync_runs, system_logs, telegram_updates |
| Служебная история схемы | d1_migrations |

Основной ключ orders.id, number уникален. order_items и order_events имеют FK на orders; sessions.staff_id — FK на staff; staff references в orders сохраняются. Внешние ключи на Google Sheets физически невозможны, проверяются валидатором. Старый delivery_method и fulfillment_method имеют разные исторические значения; действующим бизнес-полем является fulfillment_method. Не удалять столбцы phone, recovery_hash и delivery_method без совместимой миграции и аудита всех окружений. 

## Валидация без изменения данных

```sh
npm run audit:data -- items.csv categories.csv
```

Передать CSV-снимки двух листов. Скрипт выдаёт JSON с количеством строк и кодами ошибок, возвращает 1 при нарушении контракта, 2 при ошибке чтения. Ничего не записывает в Sheets или D1. Номера записей соответствуют CSV без пустых строк (парсер пропускает пустые строки). Проверяет обязательные и повторяющиеся заголовки, обязательные поля, уникальность SKU/ID/имён, группы, связи, булевы значения, цену и URL. Валидация формата URL не является сетевой проверкой изображения.

Автоматические тесты включены в npm test. Валидатор не включён в боевой импорт: существующие ошибки необходимо разобрать до переключения на строгий контракт. Двусторонняя синхронизация, UI редактирования и изменение runtime идентификаторов требуют отдельных согласованных работ.

## Служебный снимок проверки

`settings.catalog_sync_baseline_v1` содержит только идентификаторы и SHA-256 отпечатки нормализованных исходных записей, групп и категорий. Хранится последний успешный снимок, не копия каталога. `sync_runs.details_json` содержит агрегаты, предупреждения и статус проверки Apps Script. Успешная фиксация выполняется атомарно с compare-and-swap предыдущей версии. Известный экспериментальный повтор SKU учитывается мультимножеством; точная идентификация неоднозначных дублей невозможна. Генерация кэша берётся из updated_by этой служебной записи.
