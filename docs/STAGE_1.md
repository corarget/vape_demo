# Этап 1 — техническая стабилизация

Базовый коммит: b0c3fe29f1a6d4709682f7579c329663e506fac5.

## Решения

- main и violet-shop-staging — канонический код и проверочное окружение. Старые базы не трогаем.
- HTML — исходники; два .mjs-файла генерируются. Проверка не перезаписывает рабочее дерево.
- Устаревший локальный server.mjs не входит в npm scripts и не эквивалентен Worker. Удалён; локальная разработка — Wrangler.
- Повреждённый scripts/google-sheets-sync.gs удалён из дерева; восстановление возможно через Git. Единственный исходник — scripts/catalog-sheets.gs. Ничего в Google Apps Script не развёртывалось.
- Старые ветки сохранены: codex/white-label-roadmap (PR #2 содержит незавершённые изменения), codex/orders-inventory (незавершённая работа), codex/white-label-foundation и codex/stage-1-stabilization (история). Не сливать старые ветки целиком.
- Медиа и базы данных не удаляются, миграции не запускаются в рамках этой чистки.

## Критерии проверки

1. npm ci и npm test успешно проходят в CI.
2. Сгенерированные модули совпадают с HTML, исходники UTF-8, синтаксис проверен.
3. Перед публикацией сверить целевой Worker и SHA.
4. Отдельно проверить реальные сценарии в браузере и Telegram; статические проверки их не заменяют.

## Декомпозиция и проверки

- Общие HTTP, криптография, D1, авторизация и конфигурация вынесены в lib/ без изменения контрактов.
- Два перекрытых объявления в admin.html удалены; действующие реализации оставлены.
- tests/stage1.test.mjs проверяет инфраструктуру, базовые маршруты и отсутствие повторных объявлений.
- Миграция 0008 приведена к варианту без явной транзакции. CI проверяет все миграции на временной локальной D1.
- CI проверяет также dry-run сборки Wrangler без публикации.
- Мастер копирования включает lib/, чтобы структурная правка не ломала существующий скрипт.

## Границы этапа

Предметные обработчики и встроенный JS не переписываются полностью без требований и тестов последующих этапов. Старые ветки сохраняются как история незавершённых задач; не являются источником сборки. Проверка реальных интеграций, модель данных и UI отнесены к последующим этапам. Не менять удалённые базы, секреты или таблицы.
