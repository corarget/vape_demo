# White-label: запуск копии для нового клиента

## Модель передачи

Каждый заказчик получает отдельный Worker и отдельную D1-базу. Это изолирует заказы, сотрудников, настройки и аналитику. Исходный репозиторий остаётся шаблоном; клиенту не нужны доступы к GitHub или Cloudflare.

- Разработчик создаёт и обслуживает инфраструктуру.
- Клиент получает роль менеджера в своём магазине.
- Клиент подключает собственную Google Sheets через админку.
- Оформление и категории настраиваются в админке.
- Экспорт/импорт JSON переносит настройки витрины между копиями, но не переносит заказы и учётные записи.

## 1. Создать копию кода

Рекомендуемый путь — автоматический мастер:

```powershell
npm install
npx wrangler login
npm run create:store
```

Он создаёт отдельный Worker и D1, генерирует конфигурацию, применяет миграции, публикует приложение и выводит одноразовый код первого владельца. Ручное редактирование Cloudflare-конфигурации не требуется.

Для ручного развёртывания оставшиеся шаги ниже описывают низкоуровневый процесс.



1. Сделать Fork или отдельную копию репозитория.
2. В корне скопировать `wrangler.template.jsonc` в `wrangler.jsonc`.
3. Задать уникальное имя Worker, например `client-acme-store`.
4. Создать отдельную D1-базу:

```powershell
npx wrangler d1 create client-acme-store-db
```

5. В `wrangler.jsonc` указать имя и ID созданной базы. Не использовать D1 ID текущего VIOLET SHOP.
6. Применить миграции и задеплоить:

```powershell
npx wrangler d1 migrations apply client-acme-store-db --remote
npm install
npm run deploy
```

## 2. Первичный владелец

Сгенерировать длинный случайный код в PowerShell:

```powershell
$bytes = New-Object byte[] 24
[Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
$bootstrap = [Convert]::ToHexString($bytes).ToLower()
$bootstrap
```

Добавить его как Worker Secret:

```powershell
npx wrangler secret put BOOTSTRAP_CODE
```

Вставить сгенерированный код в запрос Wrangler. Открыть `/admin`, войти с этим кодом и указать имя владельца. После первого успешного входа код аннулируется в D1. Затем удалить secret:

```powershell
npx wrangler secret delete BOOTSTRAP_CODE
```

## 3. Подключить таблицу заказчика

В админке открыть **Каталог и синхронизация**:

1. Вставить ссылку на Google Sheets и GID нужного листа.
2. Таблица должна быть доступна Worker для чтения по CSV-экспорту (например, доступ по ссылке с правом просмотра).
3. Нажать **Проверить таблицу**.
4. Проверить сопоставление обязательных полей: название, категория, цена и уникальный ID варианта (product_key или SKU).
5. При необходимости прикрепить CSV-шаблон — файл сохраняется в D1 вместе с заголовками и сопоставлением.
6. Нажать **Синхронизировать сейчас**.

Исходная таблица не изменяется. Категории витрины появляются из данных листа. Для синхронизации названий и изображений можно добавить необязательные столбцы `category_label`, `category_image_url` и `category_icon`; менеджер также может задать публичные названия, изображения, иконки, порядок и видимость отдельно в разделе **Категории**.

## 4. Оформление и перенос конфигурации

В разделе настроек магазина способы получения включаются независимо:
- **Метро** — включено по умолчанию.
- **Самовывоз** — включён по умолчанию.
- **Доставка на дом** — выключена по умолчанию; после включения появляется в корзине.

Расписание и длительность слотов настраиваются внутри админки. Вместимость считается отдельно для каждого способа получения; временные ограничения можно задавать для метро, самовывоза, домашней доставки или всего магазина. Адрес и домофон показываются только при выборе доставки на дом.

Фотографии товаров берутся из поля `image_url` таблицы и показываются в карточках, карточке товара и корзине. Для новых товаров используйте доступные по HTTPS ссылки на изображения.

В **Брендинг и копирование** настроить:
- короткое описание, логотип и текст главной;
- основной и дополнительный цвета, фон и цвет карточек;
- сортировку по умолчанию;
- сбор обезличенной аналитики.

В разделе **Категории** задать названия, HTTPS-ссылки на изображения, иконки, порядок и видимость.

Кнопка **Экспортировать настройки** создаёт JSON без секретов и клиентских данных. В новой копии выбрать **Импортировать настройки**, затем подключить собственную таблицу. ID исходной таблицы намеренно не переносится.

## 5. Передать доступ клиентскому админу

1. Открыть **Команда → Создать приглашение**.
2. Выбрать роль **Менеджер** и указать имя клиента.
3. Передать ему одноразовый код и ссылку на `/admin`.
4. После входа клиент управляет заказами, слотами, каталогом, категориями, аналитикой, внешним видом и интеграциями из своей панели.

Не передавать клиенту BOOTSTRAP_CODE, GitHub token, Cloudflare API token или BOT_TOKEN.

## 6. Подключить дополнительные интеграции

- Для Telegram создать отдельного бота клиента, добавить его токен как secret `BOT_TOKEN`, затем настроить чат и webhook в админке.
- Онлайн-эквайринг подключать отдельным платёжным провайдером после согласования договора и реквизитов клиента.
- Для домена клиента добавить отдельный hostname в Cloudflare и проверить HTTPS.

## Что входит в перенос JSON

Включается: настройки магазина, бренд-оформление, тема, расписание, категории, шаблон CSV и сопоставление полей.

Не включается: ID Google Sheets, заказы, сотрудники, приглашения, сессии, customer tokens, Telegram bot token и Cloudflare secrets.
