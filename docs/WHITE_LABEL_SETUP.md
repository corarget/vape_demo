# White-label развёртывание

## Принятая архитектура

Каждый клиент получает отдельный Cloudflare Worker и отдельную D1. Заказы, пользователи, роли, настройки и журнал аудита физически не смешиваются с данными других магазинов. Общий репозиторий является шаблоном исходного кода, а не общей базой клиентов.

Идентичность окружения задаётся переменными: `STORE_ID`, `STORE_NAME`, `STORE_LOCALE`, `STORE_TIMEZONE`, `STORE_CURRENCY`. Каталог подключается отдельно через Google Sheets. Секреты хранятся только в Cloudflare Secrets.

## Автоматический запуск

1. Установить зависимости: `npm ci`.
2. Авторизоваться: `npx wrangler login`.
3. Запустить: `npm run create:store`.
4. Указать ID, название, локаль, часовой пояс IANA и валюту ISO 4217.

Мастер сначала проверяет шаблон, затем создаёт отдельную D1, копирует полный пакет (код, HTML, assets, миграции, скрипты, тесты и документацию), выполняет `wrangler deploy --dry-run`, применяет миграции и публикует Worker. Одноразовый код владельца выводится только в терминал.

## Ручной шаблон

Для ручного развёртывания скопировать `wrangler.template.jsonc`, заменить slug и новый `database_id`, затем выполнить `npm run verify`, миграции и deploy. Нельзя повторно использовать staging/prod D1 другого магазина.

## Проверка изоляции

- уникальные Worker name и `STORE_ID`;
- уникальные D1 database_id;
- отдельные Cloudflare Secrets и Telegram webhook;
- отдельная Google Sheets таблица или явно согласованный источник;
- экспорт настроек не переносит D1 и секреты;
- staging и production считаются разными окружениями и не используют одну D1.

## Ограничения

Мастер требует доступ Cloudflare с правами Workers и D1. Созданная D1 не удаляется автоматически при ошибке после её создания — это защищает от неявного удаления данных; незавершённый ресурс удаляется вручную после проверки. Кастомный домен, Telegram-бот и заполнение таблицы подключаются отдельно. UI остаётся общим шаблоном и настраивается через админку.
