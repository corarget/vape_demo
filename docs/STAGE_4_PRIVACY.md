# Этап 4 — приватность и барьеры приёмки

Дата ревизии: 2026-11-24. Только технический аудит; не является заключением о правомерности коммерческой эксплуатации.

## Область обработки данных (по схеме и коду)

| Хранилище | Содержание | Ограничения / открытые риски |
|---|---|---|
| D1 orders и order_items | идентификаторы, имя, адрес, комментарии, исторические поля телефона, состав, служебные идентификаторы | персональные и транзакционные сведения; необходимо установить сроки хранения, правила удаления и основание обработки |
| D1 order_events | история изменений, идентификаторы участников, комментарии | произвольные сообщения могут содержать персональные сведения; доступ и минимизация требуют дополнительной ревизии |
| D1 sessions, staff_invites, staff | хеши сессий и кодов, идентификация сотрудников | сроки действия существуют; периодическая очистка, отзыв доступа и права субъектов требуют определения |
| D1 analytics_events | псевдонимный посетитель, события, исторический свободный текст поиска | запись свободного текста прекращена; старые значения не удалялись, метаданные событий также требуют минимизации |
| D1 system_logs, sync_runs | технические ошибки и идентификаторы | исключены некоторые сырые исключения; исторические записи и оставшиеся диагностические поля требуют отдельной проверки |
| D1 telegram_updates | идентификаторы обновлений и время | срок хранения не установлен |
| Браузер | технический токен исторической сессии, локальные настройки, состояние интерфейса | локальное состояние не является достоверной идентификацией; нельзя хранить Telegram initData в persistent storage |
| Telegram | внешняя обработка подписанной идентификации и сообщений | внешняя передача данных; требуется отдельное определение правовых оснований и допустимости |
| Cloudflare | журналы исполнения и сетевые метаданные | конфигурация observability включена; фактические сроки хранения и доступ к логам не подтверждены |

## Решения текущего этапа

- Не удалять существующие данные автоматически. Для будущей политики определить оператора, юрисдикцию, цели, правовое основание, сроки по категориям, порядок запроса доступа/удаления, резервные копии и исключения. Утвердить до запуска.
- Не публиковать токены, реальные сведения или содержимое журналов при тестировании. Использовать нейтральные фикстуры.
- Ограничивать фактический объём JSON на уровне сервера, включая потоковые запросы без Content-Length. Сырые исключения не передавать в общие журналы.
- Разделять проверку кода, автоматические тесты, активную сборку и ручную проверку реального Telegram-клиента.

## Ограничение платформы

Официальные [Telegram Bot Platform Developer Terms](https://telegram.org/tos/bot-developers), проверенные 2026-11-24, запрещают использование приложений для торговли или содействия продаже регулируемых товаров. Наличие возрастного окна или успешного CI не устраняет этот запрет. Для существующего проекта это барьер, а не задача оптимизации пользовательских сценариев. Не включать коммерческие сценарии с регулируемыми товарами; дальнейшую универсальную разработку проверять на нейтральных нерегулируемых фикстурах. Применимые местные нормы и конкретный оператор пока не определены.
